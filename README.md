# Ketology — продуктовый лендинг

Многоязычная страница без сборщика и npm. Тексты лежат отдельно от вёрстки,
на выходе — готовый фрагмент для вставки в еком `ru.siberianhealth.com`.

## Как это устроено

```
src/page.ru.html          РАЗМЕТКА. Правится только когда меняется вёрстка
extract.py                page.ru.html → template.html + content/ru.json
src/template.html         СГЕНЕРИРОВАН. Вёрстка с плейсхолдерами {{ключ}}
src/ecom-header.html      верхняя полоса navbar-top екома (язык, страна, вход)
src/ecom-footer.html      подвал оттуда же
src/ecom-css.html         3 стилевых бандла екома
content/<lang>.json       115 строк текста на язык: ru, kk, uz
build.py                  шаблон + локаль → готовые файлы
assets/*.webp             фотографии, паки, иконки, логотипы
assets/fonts/*.woff2      Gerbera Light (300) и Medium (500)

dist/<lang>/index.html    СГЕНЕРИРОВАН. Просмотр + режим правки текстов и языков
dist/<lang>/fragment.html СГЕНЕРИРОВАН. Это вставляется в еком, без редактора
editor.py                 два режима на странице (подключается из build.py)
content/languages.json    названия языков для переключателя
import_docx.py            забрать переводы из .docx обратно в JSON
```

Порядок при правке вёрстки: `src/page.ru.html` → `python3 extract.py` → `python3 build.py build`.
При правке только текста `extract.py` не нужен.

**Разметка одна на все языки.** Меняешь текст — трогаешь только JSON.
Добавляешь язык — добавляешь один JSON. Вёрстку при этом никто не ломает.

## Команды

```bash
python3 build.py build     # собрать все локали из content/*.json
python3 build.py handover --base https://cdn/…/   # папка для передачи в еком
python3 build.py new de    # завести новый язык (копия ru с пометками TODO)
python3 build.py check     # что не переведено, где не хватает ключей
python3 build.py find "…"  # найти ключ по тексту во всех языках
python3 build.py import-locales locales.json   # забрать языки из редактора
```

Сборка для екома — с абсолютными путями к ассетам:

```bash
python3 build.py build --base https://cdn.siberianhealth.com/ketology/
```

## Как править тексты — на странице

Страница открывается в режиме ПРОСМОТРА: обычный лендинг, ничего лишнего.
Правка включается кнопкой с карандашом в правом нижнем углу; выход из неё —
«Закрыть редактор» в панели. Если в браузере остались несохранённые правки,
на карандаше горит жёлтая точка.

Открыть `dist/<lang>/index.html`, нажать карандаш:

1. Кликнуть по тексту — фрейм обводится рамкой и встаёт в правку.
   По наведению ничего не подсвечивается, только по клику.
2. Ctrl+A, Ctrl+V — вставить перевод. Всегда вставляется чистый текст:
   шрифты и цвета из Word не переносятся. Enter даёт перенос строки.
3. Увести фокус (клик мимо или Escape) — правка сохранена, блок выглядит
   как обычно: никакой подсветки не остаётся. Сколько блоков изменено —
   показывает счётчик в панели.
4. **«Сохранить в проект»** — правки уезжают в репозиторий и становятся
   настоящими. В первый раз попросит GitHub-токен с правом записи; токен
   остаётся ТОЛЬКО в этом браузере, в репозиторий он не попадает.
   Рядом с кнопкой статус: «● есть несохранённые правки» / «✓ всё сохранено».
   При попытке закрыть вкладку с несохранёнными правками браузер переспросит.

   Кнопки «Скачать язык» и «Скачать все» остаются как запасной путь, если
   токена нет: файл `locales.json` забирается командой
   `python3 build.py import-locales locales.json`.

Тексты, которых на странице не видно (title и description для поисковика,
alt картинок), правятся в `content/<lang>.json`: панель для них из редактора
убрана. При сохранении и выгрузке они сохраняются как есть, не теряются.

Языки переключаются в панели снизу без перезагрузки: в страницу зашиты все
локали. «+ Добавить язык» создаёт копию текущего — можно сразу набивать текст.
«×» рядом с языком удаляет его. И то и другое приезжает в `locales.json`.

Как это устроено: тексты лежат рядом с сайтом в `content/*.json`, страница
читает их при загрузке. Поэтому сохранённая правка видна всем сразу, как только
GitHub Pages выкатит коммит (обычно меньше минуты) — пересобирать вручную не надо.

Единственное, что требует пересборки, — `fragment.html` для екома: там текст
вшит в разметку. После правок выполнить `python3 build.py build`.

## Как править тексты — в файлах

Единого файла «на все языки» нет: у каждого языка свой JSON. Общий у них — КЛЮЧ.
Поэтому порядок такой: найти ключ по тексту, потом поменять значение в нужных языках.

```bash
python3 build.py find "Начните худеть"
```
```
cta.title_1
  content/de.json:105  Beginnen Sie komfortabel abzunehmen
  content/en.json:105  Start losing weight comfortably
  content/pl.json:105  Zacznij chudnąć komfortowo
  content/ru.json:105  Начните худеть комфортно
```

Команда показывает ключ, все четыре перевода и номер строки в каждом файле.
Искать можно по любому языку — по русскому, по английскому, по куску фразы.

Дальше: открыть нужные файлы на этих строках, поменять значение справа от двоеточия,
затем `python3 build.py build`.

Ключи говорящие: `hero.title_1`, `compare.text_3`, `flavors.btn_2`, `cta.text_1`.
Секции: `meta`, `hero`, `composition`, `nutrients`, `compare`, `tasks`,
`flavors`, `expert`, `quality`, `cta`.

## Как добавить язык

```bash
python3 build.py new de          # content/de.json, все строки с префиксом "TODO: "
# перевести значения, префикс TODO убрать
python3 build.py check           # покажет, сколько осталось
python3 build.py build
```

`build` и `check` считают непереведённые строки и ругаются, если в локали
не хватает ключей относительно `ru.json` или появились лишние.

## Интеграция в еком

Что и как передавать — в `ИНСТРУКЦИЯ_ПО_ИНТЕГРАЦИИ.md`.
Пакет собирается командой `python3 build.py handover --base …`: три файла
языков без редактора плюс только те ассеты, которые реально используются.


Берётся `dist/<lang>/fragment.html` — это `<style>` + `<div class="ketology-lp">…</div>`,
**без шапки и подвала**: они приходят от самого екома.

Изоляция стилей проверена в обе стороны на тестовой странице с намеренно конфликтными
правилами (`*{box-sizing:content-box}`, `h1{font-family:Georgia}`, `img{border:4px}`):

- все 129 селекторов лендинга префиксованы `.ketology-lp` — в еком ничего не течёт;
- в начале фрагмента идёт защитный сброс — стили екома не садятся на лендинг.

Ассеты должны лежать по адресу из `--base`. Без `--base` пути относительные.

## Источник дизайна

Figma: `Ketology_product_LP`, файл `f0sO9fZ9FdiYG2QWRdAj1a`, нода `890:482`
(фрейм «Концепция», 1440×8360). Тексты, цвета, размеры и отступы сняты из Figma REST API,
не на глаз. Ассеты выгружены через `/v1/images` в PNG@2x и сжаты в WebP (16.7 МБ → 1.1 МБ).

## Известные расхождения с макетом

- **Шапка и подвал** в макете лежат растром. В превью вместо них — настоящая разметка
  с ru.siberianhealth.com: от шапки взята только полоса `navbar-top` (язык, страна,
  вход) — каталожное мега-меню не нужно, после экспорта шапку отдаёт сам проект.
  Во фрагмент для екома ни шапка, ни подвал не попадают.
- **Нода `736:559`** (`image 38`, 586×586) в макете лежит поверх других блоков и перекрыта.
  На странице её нет.
- **Текст «Почему большинство диет заканчиваются срывом?»** (нода `736:556`) в макете лежит
  поверх блока состава и перекрыт им. На странице не выведен — нужно решение дизайнера.

- **Опечатка в макете:** «может незначительно отличаться от предстравленной» (нода `736:682`),
  и там же фраза продублирована дважды. По решению заказчика перенесено ДОСЛОВНО —
  тексты правит не разработчик.
- **Слайдер экспертов.** Два слайда (ноды `949:773` и `975:585`), стрелки ← → рабочие.
  В макете на ОБОИХ слайдах «назад» показана неактивной — похоже на недосмотр дизайнера.
  Сделано по смыслу: на первом слайде гаснет «назад», на втором «вперёд».
- **Шапка на всех языках русская** — снята с `ru.siberianhealth.com`. В проде шапку
  отдаёт сам еком на своей локали.
- **kk и uz — итог от контентщиков** (переводы из присланных ими xlsx). 26 служебных
  ключей (alt-тексты, aria-label, meta.title) в переводах не было — там остался русский
  текст, `build.py check` их не покажет: это не TODO и не отсутствующий ключ.

## Точки перелома

Мобильная раскладка действует до 1023px включительно, с 1024px — десктоп.
Значение задано один раз, в `@media (max-width:1023px)`; отдельный `820px`
внутри неё дожимает вёрстку на телефонах.
